# MAXMERCH: A/B-тест экрана приоритизации задач

**Портфолио-кейс: MAXMERCH — вымышленный продукт; данные синтетические.** Далее проект описан внутри сценария кейса.



## Краткий вывод

В эксперименте новый экран дал **+0,54 п.п.** к доле успешных визитов (95% ДИ: **+0,09…+0,98 п.п.**, p=0,019). Результат статистически значим, но ниже заранее заданного бизнес-MDE **+1 п.п.**; пороги внедрения и защитных метрик пройдены. По заданному правилу рекомендация — **не масштабировать**, пока эффект не достигнет бизнес-порога или не будет отдельно обоснована его экономика.

В ноутбуке показаны этапы от QA данных и проверки SRM до расчёта выборки, основного теста, guardrails и решения.

## Бизнес-задача

В мобильном приложении для мерчендайзеров новый экран группирует задачи по торговой точке и показывает приоритет. Нужно оценить влияние на долю запланированных визитов, в которых выполнены все обязательные задачи, и проверить защитные метрики.

## Дизайн

- 3 000 мерчендайзеров, назначение 1:1 на уровне пользователя, закреплённое на весь эксперимент.
- 2 недели pre-period и фиксированные 6 недель эксперимента.
- Основной анализ — ITT: сравнение по назначенной группе, независимо от фактического открытия экрана.
- **H₀:** разность средней доли успешных визитов между группами равна нулю.
- **H₁:** разность не равна нулю; двусторонний тест, α = 0,05.
- Плановая мощность — 80%; бизнес-MDE — +1 процентный пункт.
- Основной вывод строится на пользовательском уровне, так как повторные визиты одного мерчендайзера зависимы.

## Файлы данных

| Файл | Содержимое |
|---|---|
| `data/visits.csv` | Плановые и фактические визиты, статусы, группа и период; содержит небольшое число точных дублей для этапа QA |
| `data/tasks.csv` | Обязательные задачи и статус выполнения в рамках визита |
| `data/events.csv` | События открытия экранов и рабочего пространства |
| `data/merchandisers.csv` | Платформа, город, стаж, команда и тип занятости |
| `data/experiment_assignments.csv` | Назначение группы и страты рандомизации |
| `data/outlets.csv` | Справочник торговых точек |
| `data/projects.csv` | Справочник проектов и клиентов |
| `data_generation_metadata.json` | Seed, размеры наборов и допущения генерации |

`visits.csv` содержит более 150 000 исходных строк. Количество уникальных визитов после удаления технических дублей и размеры всех таблиц указаны в `data_generation_metadata.json`.

Полный протокол и правила принятия решения см. в [experiment_protocol.md](experiment_protocol.md).

## Аналитический план в ноутбуке

1. Постановка H₀/H₁, основной и защитных показателей.
2. Проверка размеров групп, ключей, дублей, пропусков, временных меток и связей таблиц.
3. Предобработка, расчёт метрики из записей задач и формирование ITT-выборки.
4. Проверка баланса назначения и pre-period.
5. Оценка необходимого размера выборки из пользовательской вариативности pre-period при MDE +1 п.п., α 0,05 и мощности 80%.
6. Welch t-test на уровне мерчендайзера, 95% доверительный интервал и сравнение с наивным тестом на уровне визитов.
7. Анализ вторичных и защитных метрик, сегментов и визуализация.
8. Рекомендация с учётом статистической значимости, MDE и ограничений эксперимента.


## Запуск

CSV не включены в репозиторий: их можно воспроизвести локально фиксированным генератором. Установите зависимости из requirements.txt, выполните python generate_data.py из папки проекта, затем откройте MAXMERCH_AB_test_analysis.ipynb в Jupyter. Скрипт создаст таблицы в data/ и metadata.
